# 2026-09-08 Ubuntu DB 서버와 AWS 인프라 기초 연결

## 오늘 학습한 내용

프로젝트에서 PostgreSQL DB를 특정 팀원의 개인 PC에 설치해 여러 사람이 접속해서 사용할 수도 있다. 하지만 이런 구조에서는 해당 PC가 꺼지거나 네트워크에서 빠지면 팀 전체가 DB에 접속할 수 없게 된다.

이를 통해 **DB 자체뿐 아니라 DB가 실행되는 서버의 가용성도 프로젝트 인프라의 일부**라는 점을 이해했다.

기존 구조는 다음과 같다.

```text
팀원 PC
   │
팀원 PC ─────→ 특정 개인 PC
   │             └─ PostgreSQL
팀원 PC
```

개인 PC가 서버 역할까지 담당하기 때문에 해당 장비에 문제가 생기면 DB가 하나의 장애 지점(Single Point of Failure)이 된다.

그래서 별도의 Ubuntu PC를 DB 서버로 사용하는 구조를 준비했다.

```text
개발자 PC
    │
    ├──────────┐
    │          │
개발자 PC      │
    │          ▼
    └────→ Ubuntu Server
               │
               └─ PostgreSQL
```

Ubuntu는 단순히 운영체제를 공부하기 위해 설치하는 것이 아니라, **PostgreSQL이 지속적으로 실행될 독립적인 서버 환경을 만들기 위한 기반**이다.

## 개발 PC와 서버 PC의 역할 차이

```text
개발 PC
→ VS Code
→ Python / Django
→ SQL 작성
→ 기능 개발

서버 PC
→ Ubuntu
→ PostgreSQL
→ 팀 공용 데이터 저장
→ 여러 개발자의 DB 요청 처리
```

개발자가 자기 PC에서 코드를 수정하거나 재부팅하더라도 공용 DB 서버는 계속 동작할 수 있다.

## AWS와의 연결

지금 직접 Ubuntu 서버를 구축하는 경험은 이후 AWS 환경을 이해하는 데 연결된다.

```text
학습 환경

내 PC
↓
Ubuntu PC
↓
PostgreSQL


클라우드 환경

내 PC
↓
AWS 서버
↓
PostgreSQL / RDS
```

AWS에서는 EC2가 서버 역할을 하고, RDS는 관리형 데이터베이스 서비스 역할을 할 수 있다. 또한 VPC, 보안 그룹 같은 기능을 통해 네트워크 접근 범위와 보안을 관리한다.

## 오늘의 핵심 정리

> 서버는 단순히 성능 좋은 컴퓨터가 아니라 다른 컴퓨터의 요청을 받아 특정 서비스를 지속적으로 제공하는 컴퓨터다. 개발 PC와 서버를 분리하면 특정 개인의 PC 상태가 전체 프로젝트에 미치는 영향을 줄일 수 있다.
