### 2. Django 프로젝트의 로컬 PostgreSQL DB 복원

인수인계받은 Django 프로젝트에서 DB 설정을 추적하고, 전달받은 SQL dump를 로컬 PostgreSQL의 Clone DB에 복원하는 전체 흐름을 이해했다.

핵심 흐름:

```text
Django 코드
   ↓
DB 설정(settings.py / .env)
   ↓
Local PostgreSQL
   ↑
psql -f 로 SQL dump 복원
   ↑
SQL dump
   ↓
DBeaver에서 검증
```

오늘 가장 중요하게 이해한 점은 **DBeaver는 DB가 아니라 GUI Client이고, PostgreSQL이 실제 DBMS이며, `psql -f`는 SQL dump를 실제 로컬 DB 상태로 복원하는 실행 단계**라는 것이다.

상세 문서:

- [Local PostgreSQL Restore](../../DB/2026-08-25-local-postgresql-restore.md)

## 오늘 사용한 명령과 목적

```cmd
findstr /S /I "django.db.backends" *.py
```

목적: 프로젝트 전체에서 Django DB backend 설정 위치를 추적하기 위해 사용했다.

```bash
psql \
    -X -v ON_ERROR_STOP=1 \
    -h 127.0.0.1 -p 5432 \
    -U [LOCAL_DB_USER] -W \
    -d [LOCAL_CLONE_DB] \
    -f [SQL_DUMP_PATH]
```

목적: SQL dump를 로컬 PostgreSQL Clone DB에 실제로 복원하기 위해 사용했다.

실제 DB 계정, 비밀번호, 운영 정보, 개인 정보는 공개 TIL에 기록하지 않는다.

## 앞으로의 TIL 운영 방식

```text

```
