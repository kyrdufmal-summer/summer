# 2026-10-01 TIL — 미국주식 주문시간과 레퍼런스 체크 프로세스

## 오늘의 핵심

오늘은 크게 두 가지 실무 문제를 정리했다.

1. 미국주식 주문이 반복적으로 거부될 때 단순히 계좌 잔액만 볼 것이 아니라 거래 가능 시간, 주문 유형, 시장 세션, 증권사 정책을 함께 확인해야 한다.
2. 경력직 채용의 레퍼런스 체크는 단순한 평판 조회가 아니라 후보자가 제출한 경력과 실제 업무 수행 방식의 일치 여부를 검증하는 절차로 이해해야 한다.

오늘 대화에서는 서버·네트워크·배포·DB·SSH/SFTP·FTP·HTTPS·도메인·OAuth·Ubuntu 운영에 대한 신규 작업은 없었다. 따라서 기존 서버 TIL 내용을 반복하지 않고 오늘 실제로 다룬 주제를 기록한다.

# 1. 미국주식 매수 거부를 볼 때의 문제 분해

매수 주문이 거부됐다고 해서 가장 먼저 돈이 부족하다고 결론 내리면 안 된다. 주문 실패는 여러 계층에서 발생할 수 있다.

~~~text
계좌 잔액
→ 주문 가능 금액
→ 거래 가능 시장/세션
→ 현재 미국 현지시간
→ 주문 유형
→ 가격 조건
→ 증권사 주문 정책
→ 거래소 접수
~~~

잔액이 충분하더라도 다른 조건 때문에 주문이 거절될 수 있다.

## 확인 순서

### 1) 예수금과 주문 가능 금액

계좌에 표시되는 돈과 실제 주문 가능 금액은 다를 수 있다. 원화·외화 예수금, 주문 가능 금액, 미결제 주문으로 묶인 금액, 환전 완료 여부, 수수료를 포함한 실제 필요 금액을 구분한다.

### 2) 현재 거래 세션

미국주식은 정규장 외에도 Pre-market, Regular Market, After-hours 같은 세션 개념이 있다. 증권사마다 지원 세션과 주문 가능 시간이 다를 수 있으므로 실제 앱의 주문 가능 시간을 확인해야 한다.

### 3) 주문 유형

정규장 밖에서는 주문 유형이 제한될 수 있으므로 시장가, 지정가, 예약주문, 소수점 주문 중 어떤 주문인지 구분해야 한다.

# 2. 미국의 Daylight Saving Time

오늘 중요한 개념 중 하나는 미국의 Daylight Saving Time, 즉 일광절약시간제였다.

핵심은 미국 시장의 현지 운영 시간이 바뀌는 것이 아니라 한국과 미국 사이의 시차가 한 시간 달라진다는 점이다.

~~~text
미국 현지 거래소 09:30 개장
↓
미국의 DST 적용 여부
↓
한국에서 보이는 개장 시각이 한 시간 달라짐
~~~

즉 미국장이 한 시간 일찍 일한다고 보기보다 시차 계산이 한 시간 변한다고 이해하는 것이 정확하다.

해외주식 주문 문제에서는 미국 현지 날짜, 한국 날짜, 미국 동부시간, 한국시간, DST 적용 여부를 함께 확인한다.

# 3. 장애 진단과 같은 방식으로 주문 실패를 본다

이 문제는 IT 장애 분석과 사고방식이 같다.

~~~text
웹서비스: Browser → Network → DNS → HTTPS → Application → DB

금융주문: 자금 → 환전 → 주문조건 → 시간 → 증권사 → 거래소
~~~

중요한 습관은 보이는 첫 현상을 원인이라고 생각하지 않는 것이다.

# 4. 경력직 채용의 Reference Check

레퍼런스 체크는 후보자의 이전 직장 관계자에게 업무 수행과 협업 방식 등을 확인하는 절차다.

일반적으로 실제 재직 및 역할, 담당 업무, 성과, 협업 방식, 리더십, 책임감, 문제 해결 방식, 조직 적응, 퇴사 배경, 다시 함께 일할 의향 등을 확인할 수 있다.

핵심은 완벽한 사람인지 조사하는 것이 아니라 면접에서 확인한 후보자의 설명과 실제 업무 경험이 일관되는지 검증하는 것이다.

---

# 5. 레퍼런스 체크 진행 흐름

~~~text
채용회사
↓
Reference Check 업체
↓
후보자 동의
↓
Reference 대상자 정보 제출
↓
Reference 인터뷰/설문
↓
내용 정리 및 검증
↓
채용회사에 Report 전달
↓
최종 채용 판단 자료로 활용
~~~

후보자 입장에서는 요청을 받은 뒤 급하게 사람을 찾기보다 실제 업무를 구체적으로 설명할 수 있는 Reference 후보를 미리 정리해 두는 것이 좋다.

---

# 6. 후보자가 준비해야 하는 정보

Reference 후보자를 고를 때 직급이 높은 사람만 찾는 것이 목적은 아니다. 실제로 같이 일해서 후보자의 업무를 구체적으로 설명할 수 있는 사람이 중요하다.

~~~text
직속 상사 → 업무성과·책임범위·문제해결
동료 → 협업·커뮤니케이션
프로젝트 관계자 → 실제 프로젝트 역할과 기여도
~~~

Reference 대상자에게는 과장된 답변을 부탁하기보다 본인이 지원한 역할, 주요 경력, 연락이 갈 수 있다는 사실을 미리 전달하는 것이 적절하다.

---

# 7. 면접 답변과 Reference의 일관성

레퍼런스 체크에서 특히 중요한 것은 일관성이다.

예를 들어 면접에서 프로젝트 전체를 리드했다고 설명했는데 Reference에서는 실무 일부를 담당했다고 확인되면 경력의 신뢰도 문제가 될 수 있다.

따라서 이력서의 직책, 프로젝트 기간, 실제 역할, 팀 규모, 성과 수치, 이직 사유, 상사·동료와의 관계를 사실 기준으로 다시 점검한다.

레퍼런스 체크 직전에 새로운 이야기를 만드는 것이 아니라 이미 제출한 이력서와 면접 답변을 정렬하는 것이 중요하다.

# 8. 데이터 관점에서 본 Reference Check

Reference Check도 데이터 검증 과정으로 볼 수 있다.

~~~text
후보자 주장 = Candidate Data
이력서 = Document Evidence
면접 = Interview Evidence
Reference = External Evidence

여러 Source
↓
Cross Validation
↓
Consistency Check
↓
Decision
~~~

한 데이터만 보는 것이 아니라 서로 다른 Source를 연결해 의사결정의 신뢰도를 높이는 구조다.

# 9. 오늘 두 문제의 공통점

미국주식 주문 거부는 돈이 있는데 왜 주문이 안 되는가에서 시작하지만 잔액 하나만 보지 않고 시간·세션·주문조건·증권사 정책을 확인해야 한다.

Reference Check도 면접 결과 하나만 보는 것이 아니라 이력서·면접·외부 Reference의 일관성을 확인한다.

두 문제 모두 단일 정보만으로 결론을 내리지 않고 여러 데이터 소스를 교차 검증한다는 공통점이 있다.

# 10. 실무에서 가져갈 원칙

1. 오류 메시지가 보이면 바로 원인을 단정하지 않는다.

이 원칙은 투자 주문, 채용, 서버 장애, DB 검증, VOC 분석에도 그대로 적용할 수 있다.
